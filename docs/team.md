# Командная работа

Репозиторий: https://github.com/nikita42423/bm25-gumc-admission

Главное правило: **каждый меняет только файлы своей зоны** и отправляет работу
через свою ветку и Pull Request. В `main` напрямую пушит только капитан.

## Кто за что отвечает

| Участник | Зона | Можно менять | Задачи |
|---|---|---|---|
| Кузнецов Никита (капитан) | Интеграция + код поиска | `app/*.py`, `app/search/`, `scripts/`, `tests/` (кроме `tests/manual/`), `spec/tech/architecture.md`, `requirements.txt` | — |
| Колупаев Николай | Продукт и интерфейс | `app/static/`, `spec/product/`, `docs/interface/`, `tests/manual/` | [docs/tasks/kolya.md](tasks/kolya.md) |
| Тошниёзов Жавохирбек | Корпус и benchmark | `data/`, `benchmark/`, `spec/tech/rag.md` (раздел «Корпус») | [docs/tasks/javohirbek.md](tasks/javohirbek.md) |

**Общие файлы меняет только капитан:** `README.md`, `AGENTS.md`, `CHANGE_HISTORY.md`,
`.gitignore`, `docs/team.md`, `docs/tasks/`.
Нужно что-то изменить в чужом или общем файле — напиши владельцу, а не правь сам.

## Как отправлять работу

### Один раз: подготовка
1. Принять приглашение в репозиторий (придёт на почту от GitHub).
2. Склонировать и запустить проект:
   ```bash
   git clone https://github.com/nikita42423/bm25-gumc-admission.git
   cd bm25-gumc-admission
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python -m app
   ```
   Открыть http://localhost:8000 — должен открыться чат.
3. Указать своё имя для коммитов (один раз на компьютере):
   ```bash
   git config --global user.name "Имя Фамилия"
   git config --global user.email "почта@от.github"
   ```

### Каждый раз: задача → ветка → Pull Request
1. Обновить `main`: `git checkout main` и `git pull`.
2. Создать свою ветку: `git checkout -b kolya/clear-chat` (имя ветки: `<кто>/<что делаю>`).
3. Сделать изменения **только в файлах своей зоны**.
4. Проверить, что проект запускается (`python -m app`) и ничего не сломалось.
5. Закоммитить и отправить:
   ```bash
   git add <свои файлы>
   git commit -m "Интерфейс: кнопка «Очистить чат»"
   git push -u origin kolya/clear-chat
   ```
6. На GitHub открыть Pull Request в `main`. В описании написать: что сделано и как проверить.
7. Капитан проверяет, при необходимости просит поправить, затем сливает в `main`.

### Правила коммитов
- Сообщение на русском: `<Зона>: <что сделано>`. Например: `Benchmark: добавлены 5 вопросов`.
- Один коммит — одно логическое изменение.
- Не коммитить: `.venv/`, `.env`, ключи API, личные файлы.
- `CHANGE_HISTORY.md` обновляет капитан при слиянии — по описанию из Pull Request.

## Если что-то пошло не так
- Конфликт при слиянии или непонятная ошибка git — не удалять ничего, написать капитану.
- Задача непонятна или блокирована — написать капитану, а не делать «как получится».

## Защита
Каждый участник должен уметь:
1. запустить проект (`python -m app`);
2. рассказать путь запроса: **вопрос → поиск BM25 по фрагментам документов → LLM формирует ответ → пользователь видит ответ и источник**;
3. показать и объяснить свою часть работы.
