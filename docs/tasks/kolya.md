# Задачи: Колупаев Николай — «Продукт и интерфейс»

## О проекте за 1 минуту
«Помощник абитуриента ГУИМЦ» — сайт-чат для абитуриентов с нарушениями слуха и их родителей.
Пользователь пишет вопрос → сервер ищет подходящие фрагменты в документах приёмной комиссии
(поиск BM25) → LLM пишет короткий ответ → пользователь видит ответ и источник.

Твоя зона — то, что видит пользователь: внешний вид чата, сценарии работы, описание продукта.
Сервер пока отвечает заглушкой (тестовым ответом) — для твоих задач это нормально.

## Что можно менять
Только эти файлы и папки:
- `app/static/` — `index.html`, `css/style.css`, `js/app.js`, `img/`
- `spec/product/` — `product.md`, `scenarios.md`
- `docs/interface/prototype.md`
- `tests/manual/` — результаты ручной проверки

Всё остальное (`app/main.py`, `README.md`, `CHANGE_HISTORY.md` и т. д.) **не трогать**.
Правила работы с git — в [docs/team.md](../team.md).

## Требования к интерфейсу (не нарушать)
- Только текст: никакого звука и видео.
- Неоновый градиент (`#00ffff` → `#ff77ff`) — только на активных элементах: кнопки, подсветка слов, иконки.
- Без фреймворков и сборки: чистый HTML, CSS, JavaScript.
- Должно работать на телефоне (ширина 375 px).

## Задачи

### К1. Разобраться, как работает фронтенд
Прочитай `app/static/index.html` и `app/static/js/app.js` (около 150 строк).
Добавь в `docs/interface/prototype.md` раздел **«Как работает фронтенд»** — 5–8 предложений
своими словами: что происходит от нажатия «Найти» до появления ответа
(форма → `fetch('/api/ask')` → JSON → вывод ответа и источников → подсветка слов).

### К2. Кнопка «Очистить чат»
- Небольшая кнопка справа в шапке (иконка корзины или «×» + подпись «Очистить»).
- Нажатие удаляет все сообщения и возвращает приветствие с примерами вопросов.
- Если сообщений нет — кнопка неактивна или скрыта.

### К3. Кнопка «Скопировать ответ»
- Под каждым ответом системы — маленькая кнопка «Скопировать».
- Копирует текст ответа в буфер обмена (`navigator.clipboard.writeText`).
- После нажатия на 2 секунды меняет подпись на «Скопировано ✓».

### К4. Ручная проверка сценариев
Пройди сценарии С1–С5 из `spec/product/scenarios.md` в браузере (на компьютере и в режиме телефона:
F12 → значок телефона). Запиши результат в новый файл `tests/manual/scenarios.md`:

| Сценарий | Дата | Результат | Комментарий |
|---|---|---|---|
| С1 | … | ✅ / ❌ | … |

Если для К2/К3 нужен новый сценарий — допиши его в `spec/product/scenarios.md`.

## Как сдать
Одна ветка `kolya/interface` → один Pull Request в `main` (порядок — в [docs/team.md](../team.md)).
В описании Pull Request перечисли, что сделано по К1–К4, и как проверить.

- [ ] Кнопки «Очистить чат» и «Скопировать» работают, в том числе на ширине телефона.
- [ ] Раздел «Как работает фронтенд» написан своими словами.
- [ ] Файл `tests/manual/scenarios.md` заполнен.
- [ ] Изменены только файлы из списка выше.
- [ ] Pull Request открыт.

## Подготовка к защите
Уметь без подсказок:
1. Запустить проект: `python -m app` → http://localhost:8000.
2. Рассказать путь запроса: вопрос → поиск BM25 → LLM → ответ с источником.
3. Показать в `app.js`, где отправляется запрос на сервер и где выводится ответ.
4. Объяснить, почему интерфейс только текстовый и зачем показывать источник.
