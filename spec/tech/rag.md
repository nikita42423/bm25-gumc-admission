# RAG: поиск BM25 и ответ LLM

Ответственные (зона «BM25 и RAG»): корпус и benchmark — Тошниёзов Ж. Г.;
предобработка, индекс, BM25 и LLM — Кузнецов Н. В.

Схема: **вопрос → предобработка → поиск BM25 по индексу → top-5 фрагментов → LLM → ответ + источники.**

## 2. Документ (единица индекса)
Документ корпуса — **фрагмент**: пункт правил (например, «4.2. …») или абзац.
Длинные пункты режем на части примерно по 150 слов с перекрытием 30 слов,
короткие (меньше 20 слов) склеиваем со следующим.

Почему так: пункт правил — законченная мысль, его удобно показать как источник и передать LLM.
Целый PDF слишком велик, отдельное предложение теряет контекст.

У фрагмента есть: `id`, название документа, номер пункта, текст, ссылка на PDF.

## 3. Предобработка
Одинаковая для фрагментов и для вопросов.

1. Нижний регистр, `ё` → `е`.
2. **Токенизация** регулярным выражением `[а-яa-z0-9]+`: токен — слово или число.
   Числа сохраняем: в вопросах бывают даты, баллы, номера пунктов.
3. **Лемматизация** библиотекой `pymorphy3`: «документов», «документами» → «документ».
   Обоснование: русский язык сильно изменяется по падежам и числам; без лемматизации
   вопрос «какие документы» не найдёт фрагмент «перечень документов».
   Готовая библиотека лемматизации методичкой разрешена.
4. **Стоп-слова** (предлоги, союзы, частицы: «и», «в», «на», «для», «ли» …) удаляем —
   они есть почти в каждом фрагменте и не помогают ранжированию.

## 4. Индекс и BM25
Индекс и BM25 пишем **сами** (готовые поисковые индексы запрещены методичкой).

- Обратный индекс: `терм → {id фрагмента: TF}`.
- Храним: `DF(t)`, длину каждого фрагмента `|d|`, среднюю длину `avgdl`, число фрагментов `N`.
- IDF(t) = ln(1 + (N − DF(t) + 0.5) / (DF(t) + 0.5))
- BM25(q, d) = Σ<sub>t∈q</sub> IDF(t) · TF(t,d)·(k1 + 1) / (TF(t,d) + k1·(1 − b + b·|d|/avgdl))
- Параметры по умолчанию: **k1 = 1.5, b = 0.75**. Подбираем на benchmark (k1 ∈ [1.2; 2.0], b ∈ [0.5; 0.9]).
- Возвращаем **top-5** фрагментов по убыванию BM25.
- Если лучший результат ниже порога (подбирается на benchmark) — считаем, что ответа нет (сценарий С3).

Индекс строится при старте сервера и сохраняется в `data/index.json`.

## 5. Генерация ответа (LLM)
LLM получает вопрос и top-5 фрагментов. Шаблон промпта:

```
Ты помощник приёмной комиссии МГТУ им. Н. Э. Баумана.
Отвечай только по фрагментам ниже, коротко (2–5 предложений), простым языком.
Если в фрагментах нет ответа — так и скажи. Не придумывай.

Фрагменты:
[1] <документ, пункт>: <текст>
...
Вопрос: <вопрос пользователя>
```

Модель выбираем к контрольной точке 2. Кандидаты:
- **GigaChat API** — хорошо понимает русский, доступен из России, есть бесплатный лимит;
- **локальная модель через Ollama** (например, Qwen) — бесплатно, без ключей, но нужен мощный компьютер.

Код вызова LLM изолирован в одном модуле, чтобы модель можно было заменить.
Если LLM недоступна, показываем найденные фрагменты без сгенерированного ответа.

## 6. Оценка качества
Тестовый набор — [benchmark/queries.md](../../benchmark/queries.md).

- **Recall@5** — доля релевантных фрагментов, попавших в первые 5 результатов, в среднем по вопросам.
- **MRR** — среднее значение 1 / (позиция первого релевантного фрагмента).
- Цель: Recall@5 ≥ 0.7, MRR ≥ 0.5.
- Сравниваем варианты: без лемматизации / с лемматизацией, разные k1 и b.
  Результаты сохраняем в `benchmark/results.md`.
