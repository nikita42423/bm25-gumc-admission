# Правила репозитория

Для людей и кодинговых агентов. Сначала спецификация, потом код.

## Перед изменением кода
1. Прочитай `spec/product/` (что и для кого делаем) и `spec/tech/` (как устроено).
2. Если меняется поведение — сначала обнови нужную спецификацию.
3. Внеси изменение в код.
4. Проверь:
   - интерфейс — пройди сценарии из `spec/product/scenarios.md` (`python -m app`, http://localhost:8000);
   - API — `pytest tests`;
   - поиск — `python benchmark/run.py`, метрики не должны упасть.
5. Добавь запись в `CHANGE_HISTORY.md`.

## Ограничения
- Индекс и BM25 пишем сами — готовые поисковые библиотеки запрещены (методичка НИРС).
- Ответ пользователю — только по найденным фрагментам; без источника ответ не показываем.
- Только текст: никаких звуковых и видео-элементов в интерфейсе (аудитория — люди с нарушениями слуха).
- Неоновый градиент — только на активных элементах (см. `docs/interface/prototype.md`).
- Ключи API — только в `.env`, в Git не коммитить.

## Границы зон
Каждый участник меняет только файлы своей зоны; работа сдаётся через ветку и Pull Request.
Полная таблица «кто что может менять» — в [docs/team.md](docs/team.md).
Если задача требует изменить файл чужой зоны — остановиться и сообщить владельцу.

| Путь | Что | Владелец |
|---|---|---|
| `app/*.py`, `app/search/`, `scripts/`, `spec/tech/` | сервер, поиск, LLM, архитектура | Кузнецов Н. (капитан) |
| `app/static/`, `spec/product/`, `docs/interface/`, `tests/manual/` | интерфейс, продукт, сценарии | Колупаев Н. |
| `data/`, `benchmark/` | корпус, тестовые вопросы | Тошниёзов Ж. |
| `README.md`, `AGENTS.md`, `CHANGE_HISTORY.md`, `docs/team.md`, `docs/tasks/` | общие файлы | только капитан |
